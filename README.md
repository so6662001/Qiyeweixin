## v23 七个深化决策（v24 确认）

- 销售粘性窗口：**默认 30 天，企业可配**
- 壁厚/单重替代工程类禁用：**不一律禁，企业可配**（默认禁，可放开）
- 促销与议价：**可叠加**（先促销明牌、再议价让步，叠加后过全成本红线）
- 语音 ASR：**科大讯飞**（视觉仍 Qwen-VL，语音与视觉分供应商）
- 批次匹配：**价格相同时 FIFO**（清老货）；价格不同按报价策略/库龄优惠
- 自动跟进频率：**按客户采购频率自适应**（非固定上限，学习采购周期匹配节奏）

## 七个业务深化（v23）

1. **销售粘性分配**：客户未成交再询价优先回原销售（粘性窗口可配；进行中/近期服务 > 池抽签）
2. **替代料三类新增**：壁厚替代（矩管 2.75→2.5）/ 单重替代（理计 10kg→9kg 角钢）/ 产地替代（马钢→宝钢）；壁厚/单重需强 caveat（影响承重/用量）
3. **促销优惠引擎**：整单量 / 单规格量 / 库龄优惠（呆滞促销）；主动明牌优惠（区别于议价让步）；单价降 or 整单减
4. **多规格组合询价 + 库存即时反馈**：逐规格反馈有货/紧张/无货，联动替代/拼仓/调货
5. **语音输入**：客户发语音 → ASR 转写（通义听悟/Qwen-Audio）→ KB 校正 → 文字询价流程
6. **批次库存**：货物分批次管理（炉号/库龄/实际单重）；留货下单匹配批次；联动库龄优惠/材质书/负差
7. **自动跟进**：按客户习惯主动触达（询价未报/报价未成/周期复购/账期临近）；频率控制 + 个性化

## 钢铁领域深度知识（v21）

深化 Steel KB，补全四块决定"能否成交/按什么成交/能否替代"的行业深层数据：

| 数据 | 内容 |
|---|---|
| **材质化学成分** | 牌号标准成分（C/Si/Mn/P/S）+ 碳当量 Ceq + 客户特殊要求（低磷硫/Ceq上限）+ 材质书一炉一证 |
| **钢厂执行标准差异** | 同牌号不同钢厂国标/行标/企标 + 内控（常严于国标）+ 客户指定 |
| **捆重件重** | 包装标称重量（抄牌基础）+ 整捆/拆捆 + 点支换算 |
| **余尺负差** | 轧制重量负差 ±4~6%（国标）+ 负差让利约定 + 余尺处理 |

影响：询价要素 / 替代料兼容判断（成分+标准硬约束）/ 材质书生成 / 计量 / 报价让利。

## 计量方式决策（v20 确认）

- 配置由**业务部管理人员**维护
- 重量表（理论/抄牌）**行业标准导入 + 企业可调**
- 过磅**一律以磅单为准**（下单为预估，报价/合同明示）
- **同一询价单允许各行不同计量方式**（如螺纹过磅 + H型钢抄牌）
- **"折合吨"展示企业可配**（部分企业只报点支/按米/平方价不显吨价，部分为竞争力显示）

## 销售计量方式（v19，基础数据模型补全）

钢铁卖货有多种计量方式，不同品类在不同企业允许方式不同，需各商家配置：

| 方式 | 计量基准 | 典型品类 | 价格单位 |
|---|---|---|---|
| 过磅 | 实际称重 | 螺纹、盘螺、板材 | 元/吨 |
| 点支 | 支/根数 | 管材、小批量型钢 | 元/支 |
| 理计 | 理论重量公式 | 型材、管材 | 元/吨（理论） |
| 平方 | 面积 | 开平板、卷板 | 元/㎡ |
| 按米 | 长度 | 管材、型钢 | 元/米 |
| 抄牌 | 标牌标称重量 | H型钢、大型材 | 元/吨（抄牌） |

- 企业按"品类 × 计量方式"配置允许/禁止/默认（如螺纹只能过磅、H型钢抄牌为主、点支多数禁用）
- 价格单位/数量换算/MOQ/库存/报价构成全部按计量方式适配
- 过磅下单按预估、磅单结算为准（磅差规则可配）
- 贯穿影响询价解析、报价、构成、库存、留货、自我学习

## 微信小程序方案（v18）

确定上**微信小程序**作为页面式重交互载体。关键架构决策（多租户 SaaS 下）：

- **形态：平台统一小程序 + 企业隔离**（推荐）— 一个平台小程序，客户进入后绑定所属钢贸企业；一次审核、一个支付主体、维护成本低。大客户可升级白标小程序（增值）。
- **客户端核心**：报价详情编辑 / 留货下单 / 微信支付定金 / 查订单磅单材质书对账 / 发起询价
- **销售端**：企业微信原生（文本卡片/模板卡片）为主，销售小程序长期可选
- **身份打通**：unionid 关联微信客服 external_userid ←→ 小程序 openid
- **微信支付**：留货定金 / 付款 + 分账
- **订阅消息**：报价更新 / 留货到期 / 订单状态 / 对账单（突破微信客服 48h 窗口）
- **三层关系**：对话式兜底 ← 小程序增强 ← H5 降级
- **分期**：MVP 后一期（报价编辑+留货+支付）→ 二期（查单据+订阅）→ 三期（询价入口+我的）

**待需求方拍板**：小程序形态（平台统一 vs 白标）、微信支付资质/分账、微信开放平台账号、销售端是否要小程序、上线时机。

## 报价怎么发给客户、客户怎么操作（v17）

报价生成后 **组合投递三件套 + 双路径交互**（严格在微信能力边界内）：

- **投递三件套**：文字摘要（微信纯文本，秒读）+ PDF 报价单（存档转发）+ 交互入口（菜单消息/H5/小程序）
- **对话式（轻量）**：客户直接回 "确认"/"便宜点"/"第3行改80吨"/"要现金价" → LLM 路由到下单/议价/改量/留货/构成调整
- **页面式（重量）**：点 H5/小程序 → 逐行改数量、选开票/结算/交付方式、实时重算、一键下单/留货/议价
- **降级链**：H5 → 菜单消息 → 纯文字快捷指令（回复数字）
- 原则：**页面式是增强，对话式是兜底**——一切操作都能纯靠微信对话完成

## 报价构成模型（v16）

报价 = 基准货款 + 加工费 + 运费（送货上门/代送/自提）+ 票据贴现成本 + 账期资金成本 ± 一票制/两票制税差 − 议价让步

- 全成本红线：扣全部构成成本后校验毛利底线（按 segment）
- 报价单逐项明示；一票/两票/现款各方案对比展示
- 议价让步货币扩展为 **13 维**（新增：加工费减免 / 现金价 / 账期优惠 / 一票转两票）
- 各费率/税率/贴现率/资金成本率企业可配置

## 核心设计原则

- 内部员工 → 企业微信自建应用；外部客户 → 微信客服（官方合规，不走个人微信号协议）
- LLM 仅做理解和拼装，**所有价格/库存/订单号必须来自工具调用 + 数字占位符强制**，绝不编造（防幻觉）
- 自我学习：**学事实不学决策、学参数不学规则、学的可追溯**；冷启动 60 样本 + 7/90 天双窗 + 30 天 A/B
- 报价三档协作（Auto/Assisted/Manual）；议价始终强制升 Assisted
- 大量参数**企业可配置**（Configuration Center 多租户）
- 文件 KMS 加密；SaaS 计费 + 配额
