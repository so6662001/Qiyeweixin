# Qiyeweixin

钢铁贸易行业 · 企业微信智能机器人项目。

当前阶段：**设计阶段**（尚未开发）。详细设计见 [`DESIGN.md`](./DESIGN.md)（v5，钢铁询价自然语言深度解析）。

## 一句话方案

**企业微信「自建应用」+「微信客服」双通道** + **LLM（DeepSeek/通义千问，含 VL 视觉模型）编排** + **Function Calling 调现有业务 API** + **Topic 状态机做跨天多轮对话** + **Workflow 工单引擎处理异步流程** + **Inbound Webhook 接收业务系统反向通知** + **Media Pipeline 处理文件/图片** + **Inquiry Parser 解析询价 4 种输入** + **Steel Knowledge Base 钢铁知识库 + Default Resolver 默认值推断引擎 + 字段级溯源**。

## 询价 9 要素（v5）

品类 / 规格 / 材质 / 产地 / 长度 / 标准 / 数量 / 重量 / 单重

每个字段在解析后都带 **来源标签**：
- ✏️ 客户明确说的 (explicit)
- 🤖 默认推断（含说明，如"按您历史习惯"/"行业默认"）
- 🧮 自动计算（理论单重等）
- ✅ 客户已确认 (user_confirmed)
- ❓ 缺失待补 (critical missing)

## v5 钢铁询价 NLU 核心技术栈

| 层 | 作用 |
|---|---|
| **Aho-Corasick 实体识别** | 先把"螺四 / 中板 / 工14 / 沙钢 / DN50"等高置信实体硬规则打标，省 LLM token 也更准 |
| **Steel Knowledge Base** | 品类同义词、材质牌号（含旧称）、规格正则、钢厂别名、标准对照、理论单重表、地区习惯 |
| **LLM Function Calling** | 在标注好的基础上抽取剩余字段 |
| **Default Resolver** | 4 级默认推断：客户偏好 → 销售-客户绑定 → 地区 → 行业 |
| **Field-Level Tracer** | 每字段值 + 置信度 + 来源 + 证据链 |
| **Reask Strategy** | 只问 critical missing，最多 2 轮，剩余靠回显被动确认 |
| **客户偏好画像** | 历史询价学习；冷启动跳过；销售可覆盖 |

## 关键设计约束

- 内部员工 → 企业微信自建应用；外部客户 → 普通微信里通过微信客服
- 业务 API 不改造：ACL 适配
- LLM/VL 仅做理解和拼装，**所有价格/欠款/重量/订单号必须来自工具调用**，禁止编造
- **默认推断字段必须显式标 🤖 让客户看到**，绝不偷偷塞进 ERP
- 询价解析准确率 ≥ 90%；critical 字段必反问，非 critical 走默认 + 回显确认
- 异步流程走 `/biz/event` Inbound Webhook + Workflow Engine
- 写操作一律二次确认 + 60s 反悔窗
- 文件全程 KMS 加密；询价 1y / 财务 5y 留存
