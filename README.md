## v7 议价能力核心

### 客户砍价 6 姿势 × 让步 8 货币

| 砍价姿势 | 让步货币（保毛利的关键） |
|---|---|
| 直接砍价 / 竞品施压 / 条件交换 / 量价互换 / 多维要求 / 整单打包 | **价 / 量 / 时 / 运 / 期 / 质 / 赠 / 组** |

老销售经验：**把"降价"换成"价值替代"**。Bot 必须把 8 种让步当工具箱。

### 客户类型 × 议价节奏

| 客户类型 | 让步货币偏好 | 节奏 |
|---|---|---|
| 求利型 | 价 + 赠 + 组 | 慢让递减、末端价值替代 |
| 求量型 | 量绑定 + 价 | "加 20t 再让 ¥20" |
| 战略型 | 时 + 期 + 组 | 一次给到换长期承诺 |
| 新客 | 价（首单明牌）+ 赠 | 不缠斗 |
| 流失型 | 价（唤回） + 销售关怀 | 一次到位 |

### 整单利润优化（关键）

客户砍单 item，Bot 推荐跨项让步分配：

| 方案 | 做法 | 适合 |
|---|---|---|
| A 单点让 | 客户砍的 item 让一部分 | 求利型 |
| B 转嫁让 | 砍的 item 保价，毛利厚的让 | 当事 item 毛利薄 |
| C 分散让 | 各 item 都让一点 | 求量型 |
| D 整单一口价 | 整单总价 -¥Y | 战略客 |
| E 量绑定 | "加 20t 再让 ¥20" | 求量型 |

### 议价状态机

```
OPENING → COUNTERED → CONCEDED → AGREED / IMPASSE / ESCALATED
```

让步预算 = current_price - max(cost × (1 + min_margin), price_floor)
让步幅度递减：50% / 25% / 10% / 5%；≥ 5 轮强制转人工。

### 议价话术 LLM 安全约束

- **绝不输出**价格、库存、订单号等数字（从结构化方案直接渲染）
- **绝不许愿**（不能说"我跟老板申请下"暗示让步空间）
- 后置 DLP 扫禁词（成本/老板/亏本/底价/批价）
- 客户情绪激动 → 立即转人工
