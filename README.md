# Qiyeweixin

钢铁贸易行业 · 企业微信智能机器人项目。

当前阶段：**设计阶段**（尚未开发）。详细设计见 [`DESIGN.md`](./DESIGN.md)（v3，已对齐 8 项实际后端能力）。

## 一句话方案

**企业微信「自建应用」+「微信客服」双通道** + **LLM（DeepSeek/通义千问）编排** + **Function Calling 调现有业务 API** + **Topic 状态机做跨天多轮对话** + **Workflow 工单引擎处理异步流程** + **Inbound Webhook 接收业务系统反向通知** + **Media Pipeline 处理文件/图片**。

## 对齐的 8 项实际后端能力

| # | 能力 | 形态 |
|---|---|---|
| 1 | 查留货订单 | 同步查询 |
| 2 | 查欠款 | 同步查询 |
| 3 | 询价（销售在 ERP 里报价） | 异步工单 + 业务系统回调 |
| 4 | 查装车重量（磅单） | 同步查询 |
| 5 | 要材质书 | 同步查询 + PDF 下发 |
| 6 | 接收/查结算单 | 业务系统推 + 客户回确认（双向 + PDF） |
| 7 | 接收客户付款凭证 | 入站图片/PDF + OCR + 工单转财务 |
| 8 | 提醒销售发货 | 跨用户消息转发 + 工单 |

## 关键设计约束

- 内部员工 → 企业微信自建应用；外部客户 → 普通微信里通过微信客服（官方合规，不走个人微信号协议）
- 业务 API 不改造：由 ACL（防腐层）做字段映射、参数补齐、单位换算、缓存、重试
- LLM 仅做理解和拼装，**所有价格/欠款/重量/订单号必须来自工具调用**，禁止编造
- 异步流程（询价回推、结算单推送、付款审核结果、发货状态）走 `/biz/event` Inbound Webhook + Workflow Engine
- 写操作（提交询价、确认结算、上传付款凭证、催发货）一律二次确认 + 60s 反悔窗
- 文件全程 KMS 加密，临时签名 URL，敏感字段脱敏

详细架构图、消息流程、工单状态机、风险对策、里程碑（M1~M16）见 [`DESIGN.md`](./DESIGN.md)。
