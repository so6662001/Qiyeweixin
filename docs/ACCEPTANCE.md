# 验收标准与验收用例（Acceptance Criteria & UAT）

> 目的：为每个核心能力提供**可衡量的验收标准**和**端到端验收场景**，让需求方能判断"做出来是否符合要求"。
> 返回 [总览](../DESIGN.md)。需求溯源见 [`TRACEABILITY.md`](./TRACEABILITY.md)。

---

## 0. 验收总原则

| 维度 | 验收方式 |
|---|---|
| **功能正确** | 端到端 UAT 场景（Given-When-Then），逐场景通过 |
| **质量指标** | 量化 KPI（准确率/延迟/转化率），达标线明确 |
| **业务正确** | 真实业务数据回放 + 销售/业务人员人工评审 |
| **非功能** | 性能压测 / 安全测试 / 可用性演练 |
| **防错** | 重点验证"不该发生的"（幻觉、越权、破红线、误替代） |

验收分三阶段：① 单能力验收 → ② 端到端流程验收 → ③ 灰度真实业务验收。

## 1. 分能力验收标准（量化 KPI）

### 1.1 询价解析

| 指标 | 达标线 |
|---|---|
| 文字询价 9 要素抽取准确率 | ≥ 95%（明确给出的字段） |
| 图片/PDF 询价表识别准确率 | ≥ 90% |
| Excel 列头映射准确率 | ≥ 92% |
| 默认值推断接受率（客户不修正占比） | ≥ 85% |
| 语音转写准确率（科大讯飞+KB校正） | ≥ 92% |
| critical 字段缺失时反问触发率 | 100%（不漏问） |

### 1.2 报价

| 指标 | 达标线 |
|---|---|
| 报价构成计算正确率（税/加工/运费/贴现/资金成本） | 100%（财务核对） |
| 全成本红线拦截率（赔本报价） | 100%（绝不放过） |
| 计量方式价格单位正确率 | 100% |
| Auto 档报价响应延迟 | P95 < 3s |
| 报价单 PDF 生成成功率 | ≥ 99% |

### 1.3 议价

| 指标 | 达标线 |
|---|---|
| 让步不破全成本红线 | 100% |
| 议价话术无数字幻觉（数字均来自结构化方案） | 100% |
| 议价 5 轮内收敛或转人工 | 100% |
| 销售一键确认采纳率（建议方案质量） | ≥ 70% |

### 1.4 转人工路由

| 指标 | 达标线 |
|---|---|
| 触发场景识别准确率（无库存/未定价/品类规格空等） | ≥ 98% |
| 绑定/粘性销售优先命中率 | 100%（销售可用时） |
| ACK 超时自动转派 | 100% |
| 新人保底概率达标 | 按配置（如 ≥10%） |

### 1.5 替代料

| 指标 | 达标线 |
|---|---|
| 成分/标准不兼容时拒绝替代 | 100%（绝不误替） |
| 工程类用途禁壁厚/单重替代（默认） | 100% |
| 替代必明示替代关系 + 客户确认 | 100% |

### 1.6 自我学习 / 防幻觉

| 指标 | 达标线 |
|---|---|
| LLM 输出数字幻觉率 | 0%（占位符强制 + DLP 拦截） |
| 不学习目标白名单被改 | 0%（硬保护） |
| 冷启动客户（<60样本）误用学习结果 | 0% |
| 学习参数应用前过 5 道防护 | 100% |

### 1.7 留货 / 库存

| 指标 | 达标线 |
|---|---|
| 库存独占无超卖 | 100% |
| 批次匹配正确（价同 FIFO） | 100% |
| 留货过期自动释放 | 100% |
| 定金计算正确 | 100% |

### 1.8 非功能

| 指标 | 达标线 |
|---|---|
| 回调响应延迟 | < 1s（硬限 5s） |
| 系统可用性 | ≥ 99.5% |
| 库存数据实时性 | 5 分钟级 |
| 越权访问拦截 | 100% |
| 敏感数据（成本/毛利/画像）泄漏给客户 | 0% |

## 2. 端到端验收场景（UAT，Given-When-Then）

> 每个场景为一条可执行的验收用例。实施时用真实/仿真数据回放，逐条核对期望结果。

### UAT-01 文字询价 → 报价 → 下单（主流程）

```
Given: 已绑定客户张总（量型/普通/华东）
When:  微信发"要50吨螺四 25 沙钢的 送武汉"
Then:  ① 解析出 螺纹钢/HRB400/Φ25/50t/沙钢/武汉，长度标准默认 12m/GB（🤖标注）
       ② 缺目的地已给（武汉），无 critical 缺失 → 不反问
       ③ 查库存充足 → Auto/Assisted 报价
       ④ 报价含构成（货款+运费）+ 计量方式（过磅）+ 价格单位 ¥/吨
       ⑤ 投递：文字摘要 + PDF + 菜单
       ⑥ 回"确认" → 引导下单
验收点: 解析准确、默认值标注、报价构成正确、投递三件套、可下单
```

### UAT-02 图片/Excel/PDF 询价

```
Given: 客户发一张采购单照片（含 5 行 SKU）
When:  Bot 收到图片
Then:  ① Qwen-VL 识别 5 行 → InquiryDraft
       ② 回显逐行表格 + 置信度 + 待确认项
       ③ 客户确认/修正 → 提交询价单
验收点: 多行识别 ≥90%、回显确认、可逐行改
```

### UAT-03 口语化询价（黑话+省略）

```
Given: 客户发"中板10个100吨"
When:  Bot 解析
Then:  ① "中板"=中厚板，"10个"=10mm厚度（非数量），"100吨"=数量
       ② 牌号/定尺默认（🤖标注）
       ③ 目的地缺失 → 反问
验收点: 黑话识别、位置歧义正确、默认标注、缺失反问
```

### UAT-04 多规格组合询价 + 库存即时反馈

```
Given: 客户发"螺纹Φ25 50吨、中板12mm 100吨、H型钢HW200 20吨"
When:  Bot 解析 + 查库存
Then:  ① 逐规格反馈：①✅充足 ②⚠️紧张(60t/需100t) ③❌无货
       ② 不足→拼仓/调货建议；无货→替代(宝钢H型钢)
       ③ 有货的先报价
验收点: 多规格解析、逐规格库存状态、替代/拼仓联动
```

### UAT-05 语音询价

```
Given: 客户发语音"螺四 二五 五十吨 送武汉"
When:  科大讯飞 ASR 转写
Then:  ① 转写为文字 + KB 校正
       ② 低置信→"我听到的是：螺纹HRB400 Φ25 50吨送武汉，对吗？"
       ③ 确认后走文字流程
验收点: 转写准确率、KB校正、低置信回显确认
```

### UAT-06 询价（异步报价）→ 销售报价 → 回推

```
Given: 客户发起询价（非标，无机器报价权限）
When:  提交询价单
Then:  ① 创建询价单 + 转销售
       ② 销售在 Bot 内报价
       ③ quote.ready 回推客户（含 PDF）
验收点: 异步工单、销售 Bot 内 /reply、回推
```

### UAT-07 多轮议价 + 整单利润

```
Given: 终端企业客户（毛利底线¥200/吨），整单3品种
When:  客户"螺纹再降30"
Then:  ① 按客户类型给让步方案（求利型递减让步）
       ② 整单 Optimizer 校验：让步后整单加权毛利≥¥200/吨
       ③ 破底线→转销售；不破→出方案
       ④ 议价话术无数字幻觉
验收点: 让步曲线、整单底线(按segment)、防幻觉
```

### UAT-08 促销 + 议价叠加

```
Given: 客户整单达量优惠阈值
When:  系统报价
Then:  ① 先应用整单量优惠（明牌）
       ② 客户砍价→在促销价基础上议价让步
       ③ 叠加后过全成本红线
验收点: 促销明牌、叠加议价、全成本红线兜底
```

### UAT-09 报价后改量

```
Given: 客户已收报价（锁价中）
When:  "改成80吨"（加量）/ "改成20吨"（跌穿MOQ）
Then:  ① 加量→重算（量阶梯）→AUTO/Assisted
       ② 跌穿MOQ→给客户选项（加到MOQ/不过磅/取消）
       ③ 锁价后±5%放行/累计±10%审批
       ④ 生成新版本（保留旧版）
验收点: 改量五档决策、MOQ选项、锁价后规则、版本化
```

### UAT-10 替代料推荐（含拒绝）

```
Given-A: 客户原spec无货，贸易商客户
When-A:  报价
Then-A:  推同档异厂替代（永钢）+ 明示替代关系 + 客户确认

Given-B: 出口客户要求Ceq≤0.45
When-B:  系统找替代
Then-B:  Ceq 0.50的货【拒绝替代】+ 说明原因
验收点: 推荐明示确认、成分不兼容拒绝(100%)
```

### UAT-11 留货下单 + 批次

```
Given: 白名单客户留货50吨
When:  确认留货
Then:  ① 计算定金（品类率×客户类型）
       ② 库存独占→reserved（锁定到批次，价同FIFO）
       ③ 微信支付定金
       ④ 过期T-24/12/1h提醒→自动释放
验收点: 定金计算、批次锁定、支付、过期工单
```

### UAT-12 无库存/未定价/品类空 转人工

```
Given-A: 客户询无货规格 → 转销售（绑定/粘性优先）
Given-B: 客户询未在SKU白名单规格 → 转销售
Given-C: 客户"要点货发我"（品类规格全空）→ 反问2轮→转销售
验收点: 三类触发识别、销售路由(粘性优先)、ACK超时转派
```

### UAT-13 销售竞争分配

```
Given: 客户无绑定无粘性，团队5个销售
When:  转人工
Then:  ① 加权抽签（评分高概率大）
       ② 新人保底≥10%
       ③ 优秀销售超配额→溢出
       ④ 中签概率对销售透明
验收点: 加权抽签、保底、配额、透明
```

### UAT-14 白嫖客户软干预

```
Given: 客户ghost_score 0.65（询多买少）
When:  再次询价报价
Then:  ① 锁价缩短(24h→6h)
       ② 阶梯隐藏
       ③ 销售关怀（话术不指责）
       ④ 不公开ghost_score给客户
       ⑤ 连续活跃30天→恢复优待
验收点: 差异化体验、客情防火墙、可恢复
```

### UAT-15 自我学习 + 防幻觉

```
Given: 老客户(>60样本)历史8次询价7次12m
When:  新询价未说长度
Then:  ① 默认12m(confidence0.88)，学习足迹仅主管可见
       ② LLM话术数字用占位符渲染，无幻觉
       ③ 试图让LLM报价→数字必来自工具，DLP拦截编造
验收点: 学习默认、足迹主管可见、零幻觉
```

### UAT-16 报价投递与客户操作（双路径）

```
Given: 5行报价
When:  投递
Then:  ① 文字摘要(纯文本对齐)+PDF+菜单/H5/小程序
       ② 对话式："第3行改80吨"→改量；"便宜点"→议价；"要现金价"→构成重算
       ③ 页面式：小程序逐行编辑+全局选项(开票/结算/交付)+实时重算
       ④ H5不可用→降级菜单→纯文字
验收点: 三件套、对话式意图、小程序编辑、降级链
```

### UAT-17 一票/两票制 + 结算方式

```
Given: 客户选两票制 + 银行承兑6个月 + 账期30天
When:  报价
Then:  ① 货款13%+运费9%分项计税
       ② 含贴现成本(票面×3%×0.5)
       ③ 含账期资金成本(货值×8%×30/365)
       ④ 提示"改现金省X、自提省Y"
验收点: 税务计算、贴现、资金成本、优化提示
```

### UAT-18 计量方式（抄牌/过磅/理计）

```
Given-A: H型钢(企业配置:抄牌+过磅)
When-A:  客户要点支 → 提示"仅支持抄牌/过磅"
Then-A:  按抄牌(标称重量)报价 ¥/吨

Given-B: 螺纹过磅 → 下单预估，明示"以磅单为准"
Given-C: 无缝管理计 → 理论重量×¥/吨，可选展示折合吨(企业可配)
验收点: 配置校验、计量计价、磅单为准、折合吨开关
```

### UAT-19 自动跟进（自适应频率）

```
Given: 客户历史每月初采购
When:  月初临近
Then:  ① 按采购周期自动跟进（非固定上限）
       ② 销售个人风格话术
       ③ 静默时段不发；ghost客户不过度
       ④ 超48h窗口→小程序订阅消息
验收点: 自适应频率、个性化、防骚扰、渠道
```

### UAT-20 八项能力逐项

```
查留货订单/查欠款/查装车重量/查结算单(PDF)/要材质书(PDF)
/付款凭证(上传+OCR+转财务)/发货催办(转销售)/询价报价
逐项: Given客户请求 When Bot处理 Then正确返回/转发
验收点: 8项能力端到端各通过
```

## 3. 防错验收（重点：验证"不该发生的"）

| 防错项 | 验收（必须 0 发生） |
|---|---|
| AI 幻觉数字 | 构造诱导 prompt，LLM 不得编造价格/库存/订单号 |
| 赔本报价 | 构造低价场景，全成本红线必拦截 |
| 越权访问 | 客户A 不能查客户B 数据 |
| 敏感泄漏 | 成本价/毛利/ghost_score 不出现在客户消息 |
| 误替代 | 成分/标准不兼容的替代必拒绝 |
| 超卖 | 并发留货同批次不超卖 |
| 锁价破坏 | 锁价后大幅改量必审批 |
| 不学习目标被改 | cost_redline 等白名单不被自我学习改 |

## 4. 验收方法与阶段

### 阶段一：单能力验收
- 每个能力按 §1 KPI + §2 对应 UAT 场景
- 用仿真数据 + 边界用例

### 阶段二：端到端流程验收
- UAT-01~20 全流程串联
- 真实历史询价数据回放

### 阶段三：灰度真实业务验收
- 内部销售先用 2 周
- 部分真实客户灰度
- 销售/业务人员人工评分（解析准确度、报价合理性、话术自然度）
- 对比人工处理结果

### 验收通过标准
- §1 全部 KPI 达标
- §2 全部 UAT 通过
- §3 防错项 0 发生
- 灰度期销售满意度 ≥ 80%

## 5. 给需求方的话

> 这份文档让"做出来对不对"变得**可判断**：
> - 每个能力有明确达标线（§1）
> - 每个场景有期望结果（§2）
> - 重点防错有红线（§3）
>
> 建议：请逐条核对 §2 的 UAT 场景的"期望结果"是否符合您的真实业务预期。如有偏差，即是设计需要调整的点。
